⚠️ Why Avoid any + Replacements
⚠️
Why Avoid anyCore Concept
  • Loses autocompletion & compile-time checks
  • Bugs move from compile-time → runtime
  • Hard to maintain in large Angular apps
  • Acts as a "type escape hatch" — disables TS entirely

🔒 any vs unknown — Safety Patterns
🔒
any vs unknownCore Safety
  • any → do anything, no type checks → 💥 runtime errors
  • unknown → must narrow type before use → ✅ compile safety
  • Think of unknown: "Don't know the type yet — validate first"
// ❌ any — silent crash
let data: any = "hello";
data.toFixed(2); // TS allows, crashes at runtime

// ✅ unknown — forces type check first
let data: unknown = "hello";
if (typeof data === "string") {
  console.log(data.toUpperCase()); // ✅ Safe
}
if (typeof data === "number") {
  console.log(data.toFixed(2));   // ✅ Safe
}

  return (
    typeof obj === 'object' && obj !== null &&
    'id' in obj && 'name' in obj
  );
}

  return typeof d === 'object' && d !== null
    && 'username' in d && 'password' in d;
}

🔑 Symbol — Unique IDs
🔑
Symbol — Unique IDsAdvanced
  • Symbol() always creates a globally unique value
  • Same description ≠ same symbol — every call is unique
  • Good for guaranteed in-memory unique identifiers (no collisions)
  • Cannot be serialized to JSON → not for APIs or databases
  • Can be used as object property values or keys
type User = { id: symbol; name: string; };

const users: User[] = [
  { id: Symbol("user"), name: "Alice" },
  { id: Symbol("user"), name: "Bob"  }
];

// Even same description → NOT equal
Symbol("user") === Symbol("user"); // false !

// Find by captured reference (not by value)
const idToFind = users[0].id;
const found = users.find(u => u.id === idToFind);
console.log(found?.name); // "Alice" ✅
⚠️ Symbols are invisible in JSON.stringify() — never use them as IDs for data you send to an API or store in a DB.
🟣
Symbol vs API-safe IDs Advanced
  • Symbol → best for internal, hidden, collision-free logic
  • NOT serializable → ignored in JSON.stringify()
  • Use UUID / string for API + DB (persistent identity)
  • Symbols are perfect for private metadata & framework internals
  • Best practice → combine Symbol + UUID (internal + external)
import { v4 as uuid } from 'uuid';

const INTERNAL = Symbol('internal');

interface Task {
  id: string; // ✅ API / DB safe
  title: string;
  [INTERNAL]?: { // 🟣 internal only
    isDirty: boolean;
    lastUpdated: number;
  };
}

const task: Task = {
  id: uuid(),
  title: 'Build feature',
  [INTERNAL]: {
    isDirty: true,
    lastUpdated: Date.now()
  }
};

// ❌ Symbol removed in API payload
JSON.stringify(task);

// Output → { "id": "...", "title": "Build feature" }
⚠️ Use Symbol only for internal logic. Never use it for API/DB IDs — it disappears in JSON.
💡 Best Practice: UUID/String → external identity Symbol → internal metadata (UI state, flags, caching)

🔧
Custom Async PipeAdvanced
  • Use when you need loading / error states in the pipe itself
  • Add side effects (logging, metrics)
  • pure: false is REQUIRED — observables emit without reference change
@Pipe({ name: 'customAsync', pure: false }) // ← critical
export class CustomAsyncPipe implements PipeTransform, OnDestroy {
  private sub: Subscription | null = null;
  private latestValue: any = null;
  constructor(private cd: ChangeDetectorRef) {}

  transform(obs$: Observable<any>) {
    if (!this.sub) {
      this.sub = obs$.subscribe(v => {
        this.latestValue = v;
        this.cd.markForCheck(); // triggers view update
      });
    }
    return this.latestValue;
  }
  ngOnDestroy() { this.sub?.unsubscribe(); }
}

⚡
RxJS API Handling Patterns Advanced

  • switchMap → dependent calls (cancels previous)
  • forkJoin → parallel, wait all

Behavior Comparison Core

switchMap → A❌ B❌ C✅   // latest only
mergeMap  → A✅ B✅ C✅   // all parallel
concatMap → A→B→C       // sequential

Type Coercion (JS) Tricky
  • Implicit coercion = JS auto-converts types
  • + → prefers string, - * / → number
  • == compares after coercion, === no coercion
  • Falsy: 0, '', null, undefined, NaN, false
  • Truthy: everything else (even '0', [])
// Core behavior
'5' + 1     // "51" (string wins)
'5' - 1     // 4 (number conversion)
true + 1    // 2 (true → 1)

[] + {}     // "[object Object]" 😬
[] == false // true ❗

// Equality traps ( favorite)
null == undefined  // true
null == 0          // false
null >= 0          // true ❗ (numeric comparison)

'0' == false       // true ❗
'0' === false      // false ✅

// Real-world use case (bug)
const price = '100'; // from API
if (price + 10 > 100) {
  console.log('High'); 
} 
// '10010' > 100 → true ❗ (wrong logic)

// Fix
if (Number(price) + 10 > 100) {
  console.log('Correct');
}

// Form input example
const qty = '2'; // input field
const total = qty * 100; // 200 ✅
const wrong = qty + 100; // "210" ❗

// Boolean coercion
Boolean('')     // false
Boolean('0')    // true ❗
Boolean([])     // true ❗
⚠️ RULES:
  • Always use === (except null checks)
  • Explicitly convert API/form data → Number(), Boolean()
  • Avoid mixing types in logic (string + number)
  • Debug weird bugs by checking typeof

Memoization in JavaScript Performance
  • Caches function results to avoid recomputation
  • Works best for pure functions (same input → same output)
  • Improves performance for expensive operations
  • Uses closure or Map to store previous results
// Basic memoization
function memoize(fn) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);

    if (cache.has(key)) {
      return cache.get(key); // return cached result
    }

    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

// Use case: expensive calculation
function slowSquare(n) {
  console.log('Computing...');
  return n * n;
}

const memoSquare = memoize(slowSquare);

memoSquare(5); // Computing... → 25
memoSquare(5); // cached → 25 (no log)

// Real-world use case: API caching
const fetchUser = memoize(async (id) => {
  const res = await fetch('/api/user/' + id);
  return res.json();
});

fetchUser(1); // API call
fetchUser(1); // cached response
⚠️ Avoid memoization when:
  • Function has side effects
  • Inputs are large/complex (serialization cost)
  • Cache can grow unbounded → memory leaks

  • C = Consistency → all users see same data
  • A = Availability → system always responds
  • P = Partition Tolerance → survives network split
  • Distributed systems can only fully guarantee 2 of 3
